How a project runs

Most chatbot projects get judged on vibes. Mine are judged on a test set you can see.

  1. Audit

    I review your docs and build a test set of 50–150 real questions, each with the answer and the passage it comes from.

  2. Build

    Chunking, hybrid search and reranking, each tuned to your content and measured against the test set.

  3. Ship

    Cited answers, refusals when the docs don't cover a question, and a web widget or API that fits your stack.

  4. Report

    A short write-up on accuracy, speed and cost per question, plus where it still fails and what would fix it.

Questions

Which AI model do you use?

Whatever fits your budget and privacy needs: Claude or GPT through an API, or an open model like Llama or Qwen running on your own hardware. The test set shows which one is good enough for your docs.

Does my data leave my servers?

It doesn't have to. Everything I build can run fully locally, with no API calls.

What happens when the docs don't have the answer?

The assistant says it doesn't know, rather than guessing. Refusals are part of the test set, so you'll see how often that happens.

What do you need from me?

Access to the content (a docs repo, help-center export or folder of files), around 20 example questions your users actually ask, and a 30-minute call at the start.

Got docs people keep asking about?

Tell me what your docs cover and who asks the questions. I'll reply within a day with whether a pilot makes sense.
